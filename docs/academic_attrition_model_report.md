# 基于政策语义增强与OOF Stacking集成学习的员工流失预测模型研究报告

## 摘要

本报告围绕当前员工流失预测系统的机器学习模型进行学术化说明。模型以员工结构化人力资源数据为基础，引入政策文本语义特征与岗位匹配特征，构建“员工画像特征 + 政策环境特征”的联合表征。在预测层面，系统采用 LightGBM、Logistic Regression 与 ExtraTrees 作为一层基学习器，并通过 out-of-fold（OOF）预测训练二层 Logistic meta learner，形成面向二分类概率输出的 stacking 集成模型。该模型组合兼顾非线性表达能力、线性稳定性、树模型随机化差异与概率融合可解释性，适合处理中小企业员工流失任务中常见的样本规模有限、特征类型混合、类别不均衡和业务阈值敏感等问题。

除 AUC、Accuracy、Precision、Recall、F1 与 Top-K 名单评估外，当前版本进一步补充概率型回归评估指标，包括 R 方、RMSE、MAE 与 Brier Score。这些指标以真实流失标签（0/1）和模型预测流失概率为输入，用于衡量概率输出与真实标签之间的拟合误差和概率质量。相关指标仅在本地日志与模型评估文件中输出，不进入网页展示层。

**关键词：** 员工流失预测；LightGBM；Logistic Regression；ExtraTrees；OOF Stacking；政策语义特征；概率评估指标

## 1. 研究背景与问题定义

员工流失预测属于典型的人力资源风险识别问题。其目标并非只给出“流失/不流失”的硬分类结果，而是为管理者提供可排序、可分层、可干预的风险概率。因此，模型需要同时满足以下要求：

1. 能处理员工年龄、收入、任职年限、通勤距离、满意度、加班、岗位类别等混合型变量。
2. 能捕捉非线性和交互效应，例如加班与低满意度、远距离通勤与频繁出差、晋升等待时间与岗位停滞之间的复合风险。
3. 能在类别不均衡场景下保持对真实流失样本的召回能力。
4. 能输出稳定的概率排序，用于 Top-K 名单、重点干预名单和观察名单划分。
5. 能将政策支持、岗位匹配和宏观政策环境纳入员工侧特征，而不是仅依赖传统 HR 表格字段。

因此，当前系统没有选择单一模型，而是采用多模型互补的 stacking 集成学习框架。

## 2. 数据与特征构造

当前模型的数据输入包括两部分：员工数据和政策数据。员工数据提供个体层面的结构化特征，政策数据提供岗位和部门所处外部政策环境的文本信息。

### 2.1 员工侧特征

员工侧特征主要包括数值变量、类别变量和人工交互特征。数值变量包括年龄、月收入、通勤距离、总工作年限、在司年限、当前岗位年限、距离上次晋升年限等；类别变量包括部门、岗位、出差频率、婚姻状态、性别、是否加班等。

在原始变量基础上，系统进一步构造了与流失机制相关的交互特征，例如：

- `OverTimeFlag`：加班压力信号。
- `TravelRisk`：出差频率带来的流动风险。
- `SatisfactionIndex`：多维满意度综合指标。
- `PromotionWaitRatio`：晋升等待时间相对任职周期的比例。
- `RoleStagnationRatio`：岗位停滞程度。
- `DistanceOverTimePressure`：远距离通勤与加班压力叠加。
- `StressLoadScore`：综合压力负载。

这些特征的作用是将业务经验转化为模型可学习的数值或类别信号，使模型不完全依赖自动学习隐含交互。

### 2.2 政策语义特征

政策文本不直接作为原始长文本输入分类模型，而是先被压缩为结构化政策特征。系统通过政策主题识别、岗位/部门匹配、语义向量相似度、政策情感和时间权重等步骤，将政策信息映射为员工侧可用变量，包括：

- `policy_match_mean`
- `policy_match_max`
- `policy_match_top3_mean`
- `policy_role_match_mean`
- `policy_support_score`
- `policy_constraint_score`
- `policy_net_support`
- `policy_{topic}_exposure`
- `macro_index`

这种设计可以降低文本噪声，并使政策信息进入传统表格机器学习流程。

## 3. 模型组合选择的理论依据

当前模型采用 LightGBM + Logistic Regression + ExtraTrees + 二层 Logistic meta learner 的 OOF stacking 组合。选择该组合的核心原因是：三类基学习器在表达能力、偏差-方差特性、特征响应方式和概率输出行为上具有互补性，而 OOF stacking 能在减少信息泄露的前提下学习这些模型的融合关系。

### 3.1 LightGBM：主力非线性梯度提升模型

LightGBM 是梯度提升决策树模型，适合处理结构化表格数据。员工流失预测中的许多风险并非线性叠加，例如低收入对流失的影响可能受岗位层级、年龄段、工作年限和外部政策支持共同调节。LightGBM 能通过树结构自动捕捉非线性阈值和高阶交互。

选择 LightGBM 的主要理由包括：

1. **非线性表达能力强。** 它能学习收入、年限、满意度、通勤距离等变量之间的复杂交互。
2. **适合混合型表格特征。** 经预处理后，数值特征和 one-hot 类别特征均可被树模型有效利用。
3. **对特征尺度不敏感。** 这有助于同时处理原始 HR 指标和政策匹配分数。
4. **支持类别不均衡修正。** 当前训练过程计算 `scale_pos_weight`，以缓解流失样本较少带来的偏置。
5. **排序能力较强。** 在员工风险管理中，AUC 和 Top-K 命中能力往往比单一阈值准确率更重要，梯度提升树通常能提供较好的风险排序。

因此，LightGBM 在当前组合中承担主要的非线性风险识别角色。

### 3.2 Logistic Regression：稳定线性基准与概率约束

Logistic Regression 是经典二分类模型。虽然其表达能力弱于树模型，但它具有较低方差、较强稳定性和较好的可解释性。在 stacking 中引入 Logistic Regression 并不是为了替代复杂模型，而是为了提供一个线性、平滑、偏稳健的概率视角。

选择 Logistic Regression 的主要理由包括：

1. **提供线性可解释基准。** 如果部分变量对流失概率呈近似单调或线性关系，Logistic Regression 能稳定捕捉。
2. **降低集成方差。** 与树模型相比，线性模型通常不容易过拟合局部噪声。
3. **概率输出更平滑。** 它可为二层融合提供与树模型不同的概率分布形态。
4. **适合高维 one-hot 特征。** 员工岗位、部门、出差类别等离散变量经 one-hot 后，Logistic Regression 能有效建模。

在当前系统中，Logistic Regression 的价值不是追求单模型最高性能，而是增加集成学习中的模型多样性和稳定性。

### 3.3 ExtraTrees：随机化树集成与边界互补

ExtraTrees（Extremely Randomized Trees）是一种高度随机化的树集成模型。与梯度提升树相比，ExtraTrees 通过随机特征划分和多树平均降低方差，形成与 LightGBM 不同的决策边界。

选择 ExtraTrees 的主要理由包括：

1. **增加模型多样性。** Stacking 的收益依赖基学习器之间的差异。ExtraTrees 与 LightGBM 都是树模型，但训练机制和边界形成方式不同。
2. **降低单一提升树偏差。** LightGBM 逐步拟合残差，可能在某些局部模式上形成较强偏好；ExtraTrees 的随机划分可补充不同的模式识别路径。
3. **对噪声具有一定鲁棒性。** 多棵随机树平均后，可缓解个别异常样本或局部特征噪声的影响。
4. **适合捕捉非线性和交互。** 它同样能处理复杂特征关系，但输出概率形态与 LightGBM 不完全一致。

因此，ExtraTrees 在当前模型中主要承担“随机化非线性补充学习器”的角色。

### 3.4 为什么不用单一模型

单一模型在员工流失任务中存在明显局限。只使用 Logistic Regression 可能低估复杂非线性风险；只使用 LightGBM 可能对训练数据局部结构更敏感；只使用 ExtraTrees 可能在排序能力和精细概率区分上不如提升树。当前任务既需要可排序概率，又需要较强召回，还需要稳定输出业务名单，因此单模型方案不足以覆盖全部要求。

组合模型通过引入不同归纳偏置，使模型能从多个角度解释同一员工样本：

- LightGBM 关注梯度提升下的强非线性排序。
- Logistic Regression 关注全局线性趋势。
- ExtraTrees 关注随机化树边界和非线性补充。

这种互补性是选择多模型集成的核心依据。

## 4. OOF Stacking 与二层 Logistic Meta Learner

### 4.1 OOF Stacking 的必要性

Stacking 的关键问题是：二层模型不能直接学习一层模型在训练集上的原始拟合结果，否则会产生信息泄露和过拟合。当前系统使用 out-of-fold 机制生成一层模型对训练样本的预测概率。具体而言，训练集被划分为多个折；每一折的预测都来自未见过该折样本的一层模型。这样得到的 OOF 概率更接近真实泛化表现。

OOF 机制的作用包括：

1. **降低信息泄露。** 二层模型看到的是近似样本外预测，而不是基模型对自身训练样本的过拟合输出。
2. **提供可靠融合训练数据。** 二层模型可以学习“哪些基模型在什么概率形态下更可信”。
3. **支持泛化诊断。** OOF-AUC 与测试集 AUC 的差距可用于判断模型是否存在明显泛化不稳定。

因此，OOF stacking 是当前模型从“简单投票/平均”升级为“可学习融合”的关键环节。

### 4.2 二层 Logistic Meta Learner 的合理性

当前二层模型选择 Logistic Regression，而非更复杂的树模型或神经网络，主要基于稳健性和可解释性考虑。二层输入特征不是原始高维员工特征，而是一组紧凑的模型概率特征，包括：

1. LightGBM 概率。
2. Logistic Regression 概率。
3. ExtraTrees 概率。
4. 一层加权融合概率。
5. 基模型概率均值。
6. 基模型概率标准差。
7. 基模型分歧度。

这些特征维度较低、含义明确。使用 Logistic Regression 作为 meta learner 有以下优点：

1. **避免二层过拟合。** 二层特征数量少，复杂模型容易记忆 OOF 噪声；Logistic Regression 更稳健。
2. **融合关系清晰。** 它学习的是多个概率信号的线性组合和校正，更容易解释。
3. **保留概率输出性质。** Logistic 函数自然输出 0 到 1 之间的概率。
4. **适合小样本或中等样本。** 在员工流失这类样本规模有限的任务中，二层模型应尽量简洁。

因此，二层 Logistic meta learner 的定位是“稳健概率融合器”，而不是新的复杂特征学习器。

## 5. 阈值策略与业务名单输出

员工流失预测的业务目标不是单纯最大化 Accuracy。若流失样本占比较低，模型可以通过预测大多数员工“不流失”获得较高准确率，但这对 HR 干预没有实际价值。因此，当前系统在概率预测后进一步进行分层阈值优化和 Top-K 名单评估。

模型输出包括：

- 全量员工流失概率。
- 预测流失标签。
- 高风险名单。
- 高优先级干预名单。
- 观察名单。
- Top-K Precision、Recall 与 Lift。

这种输出方式符合人力资源管理中的干预资源约束：企业往往只能对排名靠前的一部分员工采取重点沟通、薪酬复核、培训支持或岗位发展干预。因此，Top-K 名单质量比单一全局阈值更接近实际决策场景。

## 6. 机器学习评估指标体系

当前模型评估分为三类：分类判别指标、业务名单指标和概率误差指标。

### 6.1 分类判别指标

系统已有指标包括：

- **AUC：** 衡量模型对流失员工和未流失员工的排序区分能力。
- **Accuracy：** 衡量固定阈值下整体分类正确率。
- **Precision：** 衡量预测为流失的员工中真实流失的比例。
- **Recall：** 衡量真实流失员工中被模型识别出的比例。
- **F1：** Precision 与 Recall 的调和平均。

其中，AUC 更适合衡量概率排序能力；Recall 与 Top-K Recall 更适合衡量 HR 风险预警覆盖能力。

### 6.2 业务名单指标

系统输出 Top-K Precision、Recall 和 Lift：

- **Top-K Precision：** 风险名单前 K% 中真实流失员工占比。
- **Top-K Recall：** 真实流失员工被前 K% 风险名单覆盖的比例。
- **Lift：** Top-K Precision 相对于总体流失率的提升倍数。

Lift 对业务解释尤其重要。若 Top 10% 名单的 Lift 为 3，说明该名单中的真实流失密度约为总体平均水平的 3 倍。

### 6.3 新增概率误差指标：R 方、RMSE、MAE 与 Brier Score

本次新增的指标将真实标签视为 0/1 数值，将模型输出的流失概率视为连续预测值。其目的不是把分类任务改造成普通回归任务，而是补充评估概率输出的误差质量。

RMSE 定义为：

```text
RMSE = sqrt(mean((y_i - p_i)^2))
```

其中 `y_i` 为真实标签，`p_i` 为预测流失概率。RMSE 越小，说明预测概率整体越接近真实标签。

R 方定义为：

```text
R2 = 1 - sum((y_i - p_i)^2) / sum((y_i - mean(y))^2)
```

在此场景中，R 方表示预测概率相对于“仅使用样本平均流失率”这一基准的误差改善程度。需要注意的是，二分类概率上的 R 方可能为负，这表示模型概率误差甚至大于均值基准。因此，R 方应作为概率拟合辅助指标，而不应替代 AUC、Recall 或 Top-K 指标。

Brier Score 等于预测概率与 0/1 标签之间的均方误差：

```text
Brier Score = mean((y_i - p_i)^2)
```

它越小代表概率预测越好。RMSE 则是 Brier Score 的平方根，更容易与概率尺度对应。

## 7. 本地输出设计

新增指标仅输出到本地，不展示在网页端。输出位置包括：

1. 训练日志：记录 OOF 与测试集的 R 方、RMSE 和 Brier Score。
2. `*_模型评估指标.xlsx`：在“核心指标”和“完整指标”中写入训练集、OOF 验证集和测试集的概率误差指标。
3. `*_5fold交叉验证明细.xlsx`：在折级指标中记录每折概率 R 方、RMSE、MAE 和 Brier Score。
4. `*_seed_stability_report.xlsx`：在启用多随机种子集成时记录各 seed 的概率误差指标和稳定性摘要。

这种设计保持网页界面简洁，同时为本地实验分析、论文报告和模型诊断提供更完整的量化依据。

## 8. 泛化能力与稳定性控制

当前系统通过以下机制降低过拟合风险：

1. 外层 train/test 划分保留独立测试集。
2. 一层模型使用 OOF 预测训练二层融合器。
3. LightGBM 使用正则化搜索空间和早停机制。
4. 指标同时报告训练集、OOF 验证集和测试集结果。
5. 使用 OOF/Test AUC 差距进行泛化诊断。
6. 可选 multi-seed ensemble 检查随机种子稳定性。

其中，OOF 指标比训练集内指标更接近泛化表现。报告训练集 AUC 的主要目的只是观察模型是否存在明显乐观偏差，不应将其作为最终性能依据。

## 9. 结论

当前模型组合的选择具有明确的机器学习依据。LightGBM 提供强非线性表格建模能力，Logistic Regression 提供稳定线性基准和概率平滑，ExtraTrees 提供随机化树边界和非线性补充，二层 Logistic meta learner 则在 OOF 预测基础上完成稳健的概率融合。该组合能够同时处理混合型 HR 特征、政策语义增强特征、类别不均衡和业务名单排序需求。

新增 R 方、RMSE、MAE 与 Brier Score 后，模型评估体系从“分类是否正确”和“名单是否有效”进一步扩展到“概率输出是否可靠”。这使当前系统更符合机器学习实验报告和学术论文中对模型性能、泛化能力与误差分析的完整表达要求。
